# 에마 걸기: 무료 출시 → 기능 전체 유료 전환

> 2026-11-04 변경: 소원을 거는 체험을 일본 신사 문화에 맞게 **등(灯籠) → 에마(絵馬)**로 옮겼습니다. 등은 장식용 헌등대가 되었습니다. 저장소·프로토콜·상품 ID의 내부 이름은 호환을 위해 `lantern`을 유지합니다. 아래 본문의 “등”은 현재 에마를 뜻합니다.
>
> 사용자 화면에는 **무료·유료·준비 중 같은 가격 관련 문구를 표시하지 않습니다.** 아직 유료 상품이 없는데 이런 문구가 보이면 방문자가 괜히 조심하게 되기 때문입니다. 유료 판매를 실제로 시작할 때 안내 문구를 함께 설계합니다.

합의한 방향은 **초기에는 등 달기를 무료로 체험하고, 유저가 모이면 등 달기 자체를 유료화**하는 것입니다. 일부 기본 등만 계속 무료로 제공하는 프리미엄 모델이 아닙니다. 신사 산책·참배·오미쿠지·다른 방문자 보기는 무료로 유지합니다. 결제와 가격, 계정, 공개 배포는 이번 버전에 포함하지 않습니다.

## 지금 동작하는 것

- 우측 정원으로 걸어가 등 걸기: 등 3종, 24자리, 36자 소원, 선택 이름 12자, 공개 확인.
- 방별 24개, 같은 브라우저당 방마다 활성 등 하나, 게시 기간 24시간. 기간과 개수는 임시 운영 정책이며 서버에서 결정합니다.
- 같은 방에서 즉시 보이고 소원을 읽을 수 있습니다. 내 등은 직접 내려둘 수 있습니다. 기간이 지나면 표시·자리·무료 제공 한도에서 제외합니다. 만료된 파일 레코드는 다음 변경 저장 때 정리됩니다.
- 등·소원·게시 시각·만료 시각은 `DATA_DIR/lanterns.json`에 저장합니다. Node 프로세스가 재시작하거나 방이 비어도 유지됩니다. 같은 볼륨과 같은 브라우저를 사용하면 내 등 관리가 복구됩니다.
- 브라우저는 무작위 방문 키만 보관하고 서버는 그 해시로 소유권을 확인합니다. 방문 키·해시는 다른 방문자에게 보내지 않습니다. 계정 인증을 대체하는 구조는 아니며 쿠키/저장소 삭제, 다른 기기 사용, 시크릿 모드에서는 소유권을 복구할 수 없습니다.
- 서버 저장이 성공해야 등 발급을 확정합니다. 같은 요청 중복 실행·동일 자리 동시 요청·다른 사람의 등 내리기·미출시 상품 요청·기간/결제 상태 위조를 검사합니다.
- 3D 등은 InstancedMesh로 그립니다. 새 등마다 조명이나 텍스처를 추가하지 않습니다. 양 끝 두 개의 마중등은 정원 장식이며 방문자 게시 개수에 포함되지 않습니다.

## 무료 종료를 준비한 서버 정책

기본 `LANTERN_MODE=free`에서는 현재 제공되는 등 달기가 무료입니다. 사용자 화면에는 가격·무료·유료 여부를 표시하지 않습니다. 가격을 임의로 표시하거나 가짜 결제 화면을 만들지 않습니다.

`LANTERN_MODE=paid`로 시작하면 **모든 새 등 무료 발급을 서버에서 거절**합니다. 옛 클라이언트가 무료 상품 ID, `paid: true`, 0원 금액 등을 보내도 발급되지 않습니다. 무료 기간에 건 등은 원래 만료 시각까지 유지하고, 소유자의 등 내리기는 계속 허용합니다. 산책·참배와 다른 기능은 그대로 동작합니다.

현재 `paid` 모드는 화면에 「ただいま絵馬の奉納をお休みしています」만 표시하는 발급 중지 상태입니다. 이 설정만으로 돈을 받거나 구매한 등을 발급하지 않습니다. 실제 과금은 아래 작업이 완료된 뒤 켭니다.

## 과금 연결 전 추가할 작업

1. **상품과 주문**: 모든 등 달기에 가격·통화·게시 기간을 서버 상품 ID로 부여합니다. 금액을 브라우저에서 받지 않습니다. 가격·국가·통화는 아직 정하지 않았습니다. 디자인·기간별 상품을 추가할 수 있지만 무료 기본 등 유지가 전제는 아닙니다.
2. **결제 검증과 발급 권한**: 결제 제공자의 서버 API / 서명된 웹훅으로 승인된 주문을 확인합니다. 주문 ID를 유일 키로 저장하고 한 번만 등 발급에 사용할 수 있는 권한을 생성합니다. 브라우저의 성공 페이지나 `paymentStatus`를 발급 근거로 삼지 않습니다.
3. **트랜잭션과 자리 경쟁**: 주문·발급 권한·등·자리 배정을 DB 트랜잭션으로 처리합니다. 자리 예약 만료, 결제 성공 후 자리 없음, 중복 웹훅, 서버 재시작 후 재처리까지 검증합니다. 현재 단일 프로세스 JSON 저장은 결제 원장으로 사용하지 않습니다.
4. **구매 복구와 운영**: 결제 전에 계정 또는 검증된 구매 복구 방식을 도입합니다. 기기 변경·저장소 삭제 시 등과 주문을 복구할 수 있어야 합니다. 운영자 취소, 사용자 신고, 공개 소원 관리, 차단, 삭제 이력을 마련합니다. 현재 공개 소원에는 서버 길이 검증, Vue 텍스트 이스케이프, 금지어·연락처 필터(`src/shared/moderation.ts`), 방문자 3명 신고 시 자동 내리기, 관리자 내리기가 적용됩니다. 신고 수는 서버 메모리에만 있어 재시작 시 초기화되므로, 유료화 전에는 신고·삭제 이력을 DB에 남겨야 합니다.
5. **취소·환불과 정책**: 주문·결제·등 발급 상태를 분리하고 취소 / 환불 이벤트에 맞춰 권한과 표시 상태를 일관되게 갱신합니다. 실제 판매 조건과 사용자 안내를 결정한 후 표시합니다.

6. **일본 판매 요건**: 일본에서 판매하려면 특정상거래법(特定商取引法)에 따른 판매자 표기 페이지(사업자명, 주소, 연락처, 가격, 지불·제공 시기, 환불 조건)가 필요합니다. 결제 수단은 카드 외에 PayPay·편의점 결제 등 일본에서 흔한 방식을 검토합니다. 가상 봉납이라는 점과 실제 신사와 무관하다는 점도 명시합니다.

추천 상태 흐름: `주문 생성 → 결제 확인 → 발급 권한 생성 → 자리와 등 확정 → 게시 중 → 만료 / 철회`.

## 로컬 저장 운영

`DATA_DIR` 기본값은 프로젝트의 `data/`입니다. 이 디렉터리는 Git에서 제외하며 공개 정적 파일 경로 밖에 둡니다. 운영에서는 영속 볼륨과 백업이 필요합니다. 휘발성 파일 시스템에 배포하면 재배포 시 저장이 사라질 수 있습니다. JSON 파일에는 공개 소원과 개인 소유권 해시가 함께 있으므로 정적 호스팅에 업로드하지 않습니다. 파일 권한은 소유자만 읽고 쓸 수 있게 생성합니다.

파일 저장은 임시 파일 쓰기·동기화 후 이름을 교체합니다. 읽을 수 없거나 손상된 기존 저장 파일은 조용히 초기화하지 않고 서버 시작을 실패시킵니다. 여러 Node 프로세스가 같은 JSON 파일을 동시에 쓰면 안 됩니다. 운영자는 영속 볼륨·DB·백업·내용 관리 도구를 준비한 뒤 공개 유료 서비스를 시작해야 합니다.
