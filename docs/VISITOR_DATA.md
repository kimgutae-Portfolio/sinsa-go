# 익명 방문자 기록

기록은 이 기능을 적용한 뒤 서버가 확인한 행동부터 저장합니다. 이전 버전의 접속·참배 횟수를 추정해서 채우지 않습니다. 로그인 전에는 ‘한 사람’ 대신 같은 브라우저의 무작위 방문 키를 기준으로 구분합니다. 키를 지우거나 다른 브라우저·기기를 쓰면 별도 방문자로 기록됩니다.

## 저장 항목

| 필드                                     | 의미                                                                                  |
| ---------------------------------------- | ------------------------------------------------------------------------------------- |
| `visitorId`                              | 새로고침·재접속·방 변경에도 유지되는 내부 방문자 ID. 3D 장면의 임시 접속 ID와 별도    |
| `ownerHash`                              | 기존 등 소유권과 같은 방문 키의 SHA-256 해시. 원본 키는 저장하지 않음                 |
| `accountId`                              | 현재 `null`. 추후 검증된 로그인 계정에 연결하기 위한 서버 전용 필드                   |
| `firstSeenAt`, `lastSeenAt`              | 최초·최근 서버 접속 시각, Unix milliseconds                                           |
| `lastRoom`                               | 마지막 입장한 방                                                                      |
| `connectionCount`                        | 성공적으로 방에 입장한 WebSocket 연결 수. 새로고침·재연결·방 변경·추가 탭도 증가      |
| `visitCount`                             | 방문 횟수. 다른 활성 탭이 없고 마지막 접속 뒤 30분 이상 지났으면 새 방문              |
| `prayerCount`                            | 서버가 전체 참배 동작의 완료를 확인한 횟수. 중복 요청·도중 초기화·미완료 퇴장은 제외  |
| `fortuneCount`, `emaViewCount`           | 해당 시설 근처에서 실행한 체험 횟수. 2초 이내 중복 요청 제외                          |
| `lanternHangCount`, `lanternRemoveCount` | 저장에 성공한 실제 등 발급·내리기 횟수. 같은 발급 요청 재전송은 중복 집계하지 않음    |
| `connectedMs`                            | 누적 접속 시간. 같은 방문자가 여러 탭·방에 동시에 접속해도 겹친 시간을 한 번만 합산   |
| `daily`                                  | 일본 시간 `Asia/Tokyo`의 날짜별 위 카운터. 날짜를 넘긴 접속 시간도 자정에 나누어 집계 |

누적 접속 시간은 유휴·백그라운드 상태를 포함한 **연결 시간**이며 실제 집중 시간 측정값은 아닙니다. 비정상 네트워크 단절은 서버가 연결 종료를 감지하는 시점까지 포함할 수 있습니다. 서버가 재시작한 동안의 시간은 합산하지 않습니다. 오프라인 단독 체험은 서버 집계에 포함되지 않습니다. 오미쿠지 결과나 에마 내용의 실제 열람 여부·시선은 추적하지 않고 시설 근처의 실행 요청을 셉니다.

프로필에는 실명·이메일·IP 주소·User-Agent·지속적인 이동 좌표를 저장하지 않습니다. 등 소원과 공개 이름은 기존 등 저장소에서 별도로 관리합니다. 실시간 이동 스냅샷을 사용자 활동 이력으로 쌓지 않습니다.

## 보관과 읽기

현재 환경은 Supabase의 신사 전용 테이블에 새 기록을 저장합니다. 기존 JSON은 이전하지 않고 로컬에 보관합니다. 아래 파일 설명은 `STORAGE_BACKEND=file` 모드에 해당하며, DB 저장·권한·백업·단일 서버 제한은 [Supabase 안내](SUPABASE.md)를 참고하세요.

- 경로: `DATA_DIR/visitors.json` (`DATA_DIR` 기본값 `data/`). 기존 `lanterns.json`과 별도 파일입니다.
- 누적 카운터·날짜별 집계는 서버 재시작 후 복구합니다. 현재 자동 만료 정책은 없으며 원본 행동 메시지를 무제한으로 저장하지 않습니다.
- 기본 5초마다 변경분을 원자적으로 저장하고 정상 종료 시 마지막 변경도 저장합니다. 강제 종료·전원 단절 때는 마지막 저장 이후 기록이 손실될 수 있습니다. 디스크 저장 실패 시 오류를 기록하고 메모리 변경분을 유지하여 재시도합니다.
- 파일 권한은 소유자만 읽고 쓰는 `0600`, 새 디렉터리는 `0700`입니다. 손상된 파일은 조용히 초기화하지 않고 서버 시작을 실패시킵니다.
- Git 및 정적 파일 제공 경로 밖에 저장합니다. 운영에서는 영속 볼륨·백업이 필요합니다. 여러 Node 프로세스가 같은 파일을 동시에 쓰면 안 됩니다.
- 브라우저에는 본인 요약만 보냅니다. 다른 방문자의 누적 기록, 방문 키 해시, 계정 연결 필드, 날짜별 상세 기록은 방에 방송하지 않습니다. 전체 사용자 조회는 관리자 인증을 요구하는 `/api/admin/` API에서만 제공합니다.
- 화면 왼쪽 위 방문자 수를 누르면 **私のあしあと**에서 방문·참배·밝힌 등·누적 접속 시간을 확인할 수 있습니다. 접속 시간은 약 10초 간격으로 갱신됩니다.

운영자가 로컬에서 전체 합계를 확인하려면:

```sh
npm run stats
```

방문자별 누적 기록을 CSV로 내보내려면:

```sh
npm run --silent stats -- --csv > /안전한/별도경로/visitors.csv
```

CSV에는 방문 키 해시·계정 연결 필드·날짜별 상세 데이터가 포함되지 않습니다. 최초·최근 시각은 원본 Unix milliseconds입니다. 출력 파일을 공개 정적 디렉터리에 두지 마세요. 날짜별 분석에는 비공개 JSON의 `daily`를 사용합니다.

## 향후 활용과 계정 연결

첫 방문·재방문, 일별 이용자·참배, 등 달기 전환, 방문자별 누적 이용을 집계할 수 있습니다. 기록은 결제 승인이나 구매 권한의 증거로 사용하지 않습니다. 현재 저장소는 운영 분석을 위한 단일 프로세스 프로토타입이며 결제 원장과는 별도입니다.

추후 계정을 만들면 인증이 확인된 서버 흐름에서 `visitorId`와 `accountId`를 연결하고, 기존 등 소유권과 통계를 함께 이전할 수 있습니다. 현재 계정 연결 API는 없으며, 브라우저가 보내는 계정 ID나 카운터를 그대로 저장하지 않습니다. 여러 기기 통합·중복 방문 집계의 병합 규칙과 데이터 관리 기능은 로그인 도입 시 추가합니다.

`server/visitors/repository.ts`의 인터페이스에 `server/storage/supabase.ts`의 DB 어댑터를 연결했습니다. 집계 규칙은 `service.ts`에 유지합니다. 현재는 누적 카운터와 날짜별 JSON 집계를 저장하며, 사용자 수가 늘면 날짜 집계 테이블 분리와 변경 행만 갱신, DB에서의 검색·합계 조회로 확장해야 합니다.

관리자 페이지와 접근 제어는 [관리자 안내](ADMIN.md)를 참고하세요.
