# 관리자 페이지

관리자 화면 주소는 **`/admin`** 입니다. 게임과 관리자 화면은 모두 일본어 UI를 사용합니다. 관리자 화면은 3D 장면을 로드하지 않으므로 별도로 가볍게 열 수 있습니다.

## 처음 설정

```sh
npm run admin:setup
npm run dev
```

설정 명령은 강한 무작위 초기 비밀번호를 만들고 비공개 `DATA_DIR`에 저장합니다.

- `data/admin.json`: salt와 scrypt 해시만 저장하는 인증 설정.
- `data/admin-password.txt`: 운영자가 처음 비밀번호를 확인하는 파일. 새 파일 권한은 `0600`입니다.
- 두 파일은 Git 및 정적 화면 경로에서 제외됩니다. 초기 비밀번호 파일은 관리자만 보관하고 공개 파일·공유 문서로 옮기지 않습니다.
- 이미 설정이 있으면 명령이 종료되며 기존 비밀번호를 덮어쓰지 않습니다.
- `DATA_DIR`을 지정했다면 서버와 설정 명령에 같은 값을 사용하세요.

이 프로젝트에는 초기 관리자를 설정해 두었습니다. 로컬 초기 비밀번호는 `data/admin-password.txt`에서 확인할 수 있습니다. 비밀번호 원문은 채팅이나 프런트엔드 코드에 넣지 않았습니다.

운영 환경에서 파일 대신 환경 변수로 비밀번호를 제공하려면 **서버의** `ADMIN_PASSWORD`에 14~256자의 비밀번호를 지정합니다. 이 값은 파일 설정보다 우선하며 `VITE_` 변수가 아닙니다. 게임 서버는 `.env`를 자동으로 읽으며, 호스팅 설정 또는 셸 환경 변수로도 지정할 수 있습니다.

## 화면에서 볼 수 있는 것

관리자는 선택한 저장소의 기록을 표시합니다. 현재 로컬 환경은 Supabase이며, 기존 JSON 기록은 이전하지 않았으므로 DB 전환 이후 새 기록만 집계합니다. [Supabase 안내](SUPABASE.md).

- 전체 기록 사용자 수와 현재 접속 사용자 수.
- 누적 접속·방문·참배 횟수와 현재 게시 중인 에마 수.
- 최근 7일의 접속·참배 흐름(일본 시간).
- 사용자별 접속·방문·참배·게시 중 에마·누적 발급 수, 최근 방과 최근 방문.
- 사용자 ID·방 이름 검색, 접속 중/오프라인 및 게시 중 에마이 있는 사용자 필터.
- 접속·참배·에마 수·최근 방문 정렬과 페이지 나누기.
- 사용자 상세: 첫/최근 방문, 누적 접속 시간, 운세/에마/에마 내리기 횟수, 소유 에마과 최근 30일의 집계.
- 에마 목록: 그림, 공개 소원·이름, 소유 사용자, 방·자리, 게시 시각·만료 시각, **신고 수**. 게시 중/기한 만료/보관 전체 상태와 텍스트 검색. 게시 중인 에마는 「外す」 버튼으로 바로 내릴 수 있습니다(확인 창 → `POST /api/admin/lanterns/:id/remove`, CSRF 토큰 필수, 같은 방 방문자 화면에서 즉시 사라짐).
- 현재 사용자 필터를 적용한 CSV 내보내기. CSV에는 방문 키 해시와 계정 연결 정보가 포함되지 않습니다.

에마 집계에는 차이가 있습니다. **현재 게시 중**은 실제 등 저장소의 활성 레코드 수이며, **누적 발급 수**는 사용자 기록 기능 도입 후 발급에 성공한 횟수입니다. 이전 버전에서 걸었던 에마은 현재 게시 중에는 포함되고 과거 발급 횟수를 임의로 더하지는 않습니다. 에마 내리기와 만료 뒤 다음 저장 시 기존 등 레코드가 정리되므로, ‘기한 만료’ 목록은 현재 보관된 만료 기록이며 전체 과거 이력 목록은 아닙니다. 소유자 프로필이 아직 없으면 ‘記録開始前の利用者’로 표시합니다.

사용자 ID는 익명 브라우저 식별입니다. 다른 기기나 저장소 삭제 후 같은 사람인지 관리자 화면에서 자동 판단하지 않습니다. 모든 시각은 일본 시간으로 표시합니다. 화면은 약 15초마다 갱신하고 수동으로도 갱신할 수 있습니다.

## 인증과 접근

관리자 API는 `/api/admin/` 아래에만 있습니다. 인증 전에는 사용자·에마·CSV를 반환하지 않으며, 일반 게임의 실시간 프로필에는 본인 기록만 전달합니다.

- 무작위 서버 세션과 HttpOnly / SameSite=Strict 쿠키를 사용합니다. HTTPS에서는 Secure도 설정합니다.
- 세션 최대 8시간, 요청이 없는 상태 30분 뒤 만료합니다. 관리자 화면의 자동 갱신 중에도 최대 8시간 제한은 적용됩니다.
- 세션은 서버 메모리에 있으므로 서버 재시작 시 다시 로그인해야 합니다. 사용자/에마 기록은 그대로 유지됩니다.
- 설정을 제거하거나 인증 설정이 바뀌면 기존 관리자 세션은 사용할 수 없습니다.
- 로그인/로그아웃에 요청 출처를 검사하고, 로그아웃에는 세션별 CSRF 토큰도 확인합니다.
- 로그인 실패를 연결 주소 기준으로 메모리에서 제한합니다(15분당 5회). 해당 주소를 방문자 프로필이나 통계 파일에 기록하지 않습니다.
- 관리자 응답은 `no-store`입니다. 비밀번호와 세션 토큰을 브라우저 localStorage에 저장하지 않습니다.
- 관리자 기능은 조회·검색·내보내기이며 사용자 기록 삭제나 결제 조작은 추가하지 않았습니다.

개발 서버와 `preview`는 `/api/admin`을 `8787` 서버로 전달합니다. 운영에서는 화면과 API를 같은 출처로 제공하고 HTTPS를 사용하세요. HTTPS를 종료하는 리버스 프록시에서는 신뢰하는 프록시가 실제 접속 방식에 맞게 `X-Forwarded-Proto`를 설정해야 합니다. 인터넷 공개 운영의 인증 통합·관리자별 권한·감사 로그는 사용자 수가 늘 때 추가할 수 있습니다.

## 구현 파일

- `src/admin/AdminApp.vue`, `admin.css`: 일본어 관리자 화면.
- `src/shared/admin.ts`: 조회 전용 응답 타입.
- `server/admin/auth.ts`: 관리자 비밀번호 검증과 세션.
- `server/admin/api.ts`: 접근 제어, 조회·CSV API.
- `server/admin/data.ts`: 개인 식별 해시를 제외한 사용자/에마 결합, 집계·검색·페이지 나누기.
- `scripts/admin-setup.mjs`: 기존 설정을 덮어쓰지 않는 최초 설정.
