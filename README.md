# こもれび神社 · Komorebi Shrine

Vue 3 + Vite + TypeScript + Three.js로 만든 일본 신사 체험 프로토타입입니다. [산사](https://sansatemple.com/)의 캐릭터 뒤 3인칭 시점과 드래그 탐색을 참고해, 숲속 신사에 들어와 참배하고 잠시 쉬는 공간으로 구성했습니다. 별도 GLB 파일 없이, 입체 디테일을 더한 절차적 모델과 프로젝트에 포함된 목재·잎 텍스처로 바로 실행됩니다.

## 실행

Node.js **24 LTS(권장)** 또는 **22.12 이상의 22.x**를 사용하세요.

```sh
npm install
npm run dev
```

`npm run dev`는 프런트엔드와 실시간 서버를 함께 실행합니다. 화면 기본 포트는 `5173`, 실시간 서버는 `8787`입니다. 화면 포트가 사용 중이면 다음 포트가 선택됩니다. 현재 미리보기와 같은 포트를 사용하려면:

```sh
npm run dev -- --port 4173
```

모바일은 같은 Wi-Fi에서 터미널의 Network URL로 접속하세요. WebGL과 하드웨어 가속이 필요합니다.

```sh
npm run build    # TypeScript 검사 + 프런트엔드와 Node 서버 빌드
npm start        # http://localhost:8787 · 화면과 WebSocket을 함께 제공
npm test         # 게임 로직 + 실제 WebSocket + 재접속 / 자원 해제 테스트
```

## 체험과 조작

| 조작                 | PC                                            | 모바일 / 터치                  |
| -------------------- | --------------------------------------------- | ------------------------------ |
| 걷기                 | 빈 바닥 클릭 / WASD / 방향키                  | 빈 바닥 터치 / 왼쪽 조이스틱   |
| 주변 둘러보기        | 화면 드래그                                   | 화면 밀기                      |
| 카메라 거리          | 마우스 휠                                     | 두 손가락 핀치                 |
| 체험 장소로 가기     | 하단 테미즈·참배·오미쿠지·에마 버튼 또는 시설 이름표 | 동일                    |
| 가까운 시설 상호작용 | E / 표시된 버튼                               | 표시된 버튼 / 오른쪽 터치 버튼 |
| 신사 안내            | 오른쪽 위 나침반                              | 동일                           |
| 입구로 돌아가기      | 오른쪽 위 회전 화살표                         | 동일                           |
| 이용 안내            | 오른쪽 위 물음표                              | 동일                           |
| 모달 닫기            | 닫기 / Escape / 바깥 클릭                     | 닫기 / 바깥 터치               |

- 화면 전체를 신사 공간으로 사용합니다. 캐릭터 뒤에서 배전과 마당을 바라보며 시작하고, 카메라는 캐릭터를 부드럽게 따라갑니다.
- 드래그로 카메라를 회전하면 WASD / 방향키 / 조이스틱의 이동 기준도 현재 시선에 맞춰 바뀝니다.
- 바닥을 누르면 표시된 위치까지 장애물을 피해서 걸어갑니다. 건물이나 나무를 눌러 바닥을 관통 이동하지 않도록 차단합니다.
- 하단 체험 버튼을 누르면 해당 장소로 **실제로 걸어간 뒤** 체험합니다. 이동키나 조이스틱을 조작하면 자동 이동이 취소됩니다.
- **테미즈(手水)**: 도리이 왼편 테미즈야(手水舎)로 걸어가 히샤쿠(柄杓)로 **왼손 → 오른손 → 입 → 손잡이** 순서로 약 8.8초간 몸을 정갈히 합니다. 진행 중에는 이동이 잠기고, 카메라가 수반 쪽으로 돌아갑니다. 동작은 내 화면에서만 재생되며 다른 방문자에게는 서 있는 모습으로 보입니다.
- **참배하기**: 새전함 앞으로 이동·정렬한 뒤 **두 번 절 → 두 번 박수 → 한 번 절**을 약 6.7초에 걸쳐 재생합니다. 참배 중에는 이동·중복 실행을 잠급니다.
- **오미쿠지**: 배전 왼편 오미쿠지함에서 대길 / 중길 / 소길 / 길 / 말길을 같은 확률로 뽑고 Vue 모달에 표시합니다.
- **에마**: 배전 오른편 에마카케(絵馬掛所)로 걸어가 그림 3종 중 하나와 자리를 골라 소원을 써서 겁니다. 입력하는 동안 에마 미리보기에 세로쓰기로 표시됩니다. 소원과 선택 이름은 같은 방에 공개되고, 다른 사람의 에마를 읽거나 부적절한 내용으로 신고할 수 있으며, 내 에마는 내릴 수 있습니다.
- **헌등(献灯)**: 참도 오른편에는 봉납 제등이 걸린 장식대가 있습니다. 체험 대상이 아닌 풍경입니다.
- 모달이 열리면 내 캐릭터 이동이 멈추며 다른 방문자는 계속 보입니다. 포커스 순환 / 복귀, Escape 닫기를 지원합니다.
- 초기화는 캐릭터 위치·자세·카메라 방향과 거리를 되돌립니다. 방문 표시는 유지되고 새로고침하면 초기화됩니다.

## 구현 기능

- 캐릭터 중심 원근 카메라: 낮은 3인칭 시점, 드래그 회전, 상하 각도 제한, 휠 / 핀치 거리 제한, 시점에 따른 이동 방향, 장애물 앞 카메라 거리 보정.
- 배전은 초기 버전보다 폭 2배·높이 1.4배·깊이 1.3배로 확대했습니다. 넓은 석재 참배 마당, 4단 계단, 처마 아래 기둥과 큰 새전함을 배치하며 건물 크기·충돌체·참배 위치는 `layout.ts`에서 함께 관리합니다.
- 30×30 신사 맵: 도리이, 돌길, 열린 배전, 새전함, 오미쿠지함, 에마카케, 헌등대, 석등, 지붕 있는 테미즈야, 벤치, 연못, 바위, 나무, 꽃잎.
- 곡선 처마와 개별 기와, 노출된 서까래, 회벽 박공, 목재 결, 현판, 격자문, 세 갈래로 꼰 시메나와, 글씨가 있는 에마·새전함을 구성합니다.
- 나무는 휘어진 줄기·뿌리·가지와 투명 잎 카드를 겹쳐 만듭니다. 잎 사이의 틈으로 그림자가 드리워지고 잎 끝이 미세하게 흔들립니다.
- 캐릭터는 둥근 얼굴과 머리카락, 귀·손·신발, 옷의 지퍼·주머니·솔기, 배낭 끈을 표현합니다. 어깨·팔꿈치·골반·무릎 관절을 분리해 보행과 참배를 재생합니다.
- 맵 바깥을 둘러싸는 숲 32그루, 언덕, 안개, 하늘과 옅은 구름, 따뜻한 햇빛, 잔디 1,900개로 경내와 배경을 잇습니다.
- 시각 모델과 독립적인 충돌체, 원 / AABB 충돌, 벽 슬라이딩, deltaTime 이동 및 세부 단계로 관통 방지.
- A* 경로 탐색: 빈 바닥과 체험 장소로 이동하며, 막힌 대각선 모서리를 관통하지 않습니다. 도달할 수 없는 위치는 이동하지 않습니다.
- `Idle` / `Walk` / `Pray`, 프로시저럴 걷기·호흡·절·박수, GLB `Idle` / `Walk` 클립 연결.
- `AssetLoader`: GLB 미설정 / 파일 없음 / 파싱 실패 시 기본 Geometry 사용. 초기에는 없는 모델 파일을 요청하지 않습니다.
- Pointer Events 기반 마우스 / 터치 입력, 포인터 캡처, 제스처 취소와 blur 처리.
- 반응형 화면, 하단 체험 메뉴, 근접 버튼과 월드 이름표, 방문 기록, 일시적인 환영 문구.
- WebGL 시작 실패 안내. unmount 시 RAF, ResizeObserver, 키보드·포인터·휠·visibility·WebGL 이벤트, 애니메이션, GPU 리소스와 WebGL 컨텍스트를 정리합니다.
- 익명 실시간 멀티플레이와 서버 전용 Supabase 저장을 지원합니다. 로그인, 채팅, 결제는 구현하지 않습니다.

## 게임 안의 안내창

안내·오미쿠지·에마·참배자·사운드 창은 종이색 바탕, 먹색 본문, 주홍색 강조로 통일했습니다. 제목은 일본어 명조체, 본문은 고딕체를 사용하며 작은 보조 글씨도 대비를 높였습니다. PC 체험창은 오른쪽에 열리고 배경을 흐리지 않아 신사 풍경을 계속 볼 수 있습니다. 모바일은 화면 안에서 스크롤하며, 입력 글씨는 16px로 확대합니다. 체험창을 열면 뒤의 메뉴를 숨기고 키보드 포커스를 창 안에 유지하며, 닫은 뒤에는 원래 버튼으로 돌려줍니다.

시각 규칙은 `src/styles/shrine-panels.css`에 분리했습니다. 오미쿠지 추첨·참배·에마 저장 방식은 그대로입니다.

## 신사 배경음

오른쪽 위 **「音を聴く」** 를 누르면 숲의 바람·새소리·은은한 피리·멀리 울리는 작은 방울이 섞인 48초 배경음을 재생합니다. 패널에서 **「音を休める」** 와 음량 슬라이더를 사용할 수 있습니다. 설정은 이 브라우저에 기억하며, 새로고침 후에는 사용자 클릭으로 다시 시작합니다. 모든 사운드 UI는 일본어입니다.

- 사용자 동작 전에는 음원 다운로드·AudioContext 생성·자동 재생이 없습니다. 기본 음량은 35%입니다.
- 다른 탭이나 앱으로 이동하면 일시 정지하고, 돌아오면 이어서 재생합니다. 브라우저가 재개를 막으면 다시 누르라는 안내가 나옵니다.
- 오디오 로딩 실패 시 재시도할 수 있고 게임은 계속 사용할 수 있습니다. 저장소 차단 시에도 재생할 수 있습니다.
- unmount 시 요청 중단, visibility/포인터 리스너 제거, 소스·gain 분리, 디코딩 버퍼 참조 해제, AudioContext 종료와 타이머 정리를 수행합니다. 관리자 페이지에는 오디오를 생성하지 않습니다.
- 외부 녹음 없이 직접 합성한 오리지널 음원입니다. 실제 신사 녹음·독경은 포함하지 않습니다. 음원 출처·재생성과 교체 방법은 [사운드 안내](public/audio/README.md)를 참고하세요.

## 관리자 페이지와 일본어 화면

게임의 화면·안내·운세·접근성 이름·오류/알림은 일본어입니다. 사용자가 직접 입력한 소원·이름은 원문을 유지합니다.

**`/admin`** 에서 사용자별 접속/참배 횟수와 에마 현황을 한눈에 볼 수 있습니다. 전체 요약과 최근 7일 추이, 검색·정렬·접속 상태 필터·페이지 나누기, 사용자 상세와 에마 목록(신고 수 표시·관리자 내리기), CSV 내보내기를 지원합니다. 게임과 별도 로드되며, 전체 사용자 정보는 관리자 인증 뒤에만 조회할 수 있습니다.

```sh
npm run admin:setup  # 최초 한 번만; 기존 설정은 덮어쓰지 않음
```

현재 로컬 초기 관리자 설정은 완료되어 있습니다. 초기 비밀번호는 비공개 `data/admin-password.txt`에서 확인하세요. 운영에서는 서버 `ADMIN_PASSWORD` 환경 변수 또는 비공개 설정 파일을 사용합니다. 로그인 세션은 HttpOnly 쿠키로 관리하고, 서버 재시작 시 다시 로그인합니다. 자세한 설정·집계 기준은 [관리자 안내](docs/ADMIN.md)에 있습니다.

## 익명 방문자 기록

현재 로컬 `.env`는 **기존 Supabase 프로젝트의 `shrine_*` 전용 테이블**을 사용합니다. 사용자의 선택에 따라 기존 JSON 기록은 로컬에 보관하고, 전환 뒤의 새 기록부터 DB에 저장합니다. 기존 서비스의 테이블·권한은 변경하지 않았습니다. 연결·설치·장애 처리와 운영 제한은 [Supabase 안내](docs/SUPABASE.md)를 참고하세요.

같은 브라우저의 방문자별로 **접속·방문·참배 완료·오미쿠지·에마 창 열람·에마 걸기/내리기 횟수**, 최초/최근 방문 시각, 최근 방과 누적 접속 시간을 서버에 저장합니다. 날짜별 집계는 일본 시간 기준입니다. 여러 탭의 접속 시간은 중복 합산하지 않고, 30분 이내 재접속은 같은 방문으로 묶습니다. 참배 완료와 실제 에마 저장은 서버에서 집계하므로 브라우저가 임의의 횟수를 보내도 반영하지 않습니다.

기록은 선택한 저장소에 5초마다 저장하고 정상 종료 시에도 저장합니다. `STORAGE_BACKEND=file`일 때 파일은 `DATA_DIR/visitors.json`입니다. 새로고침·서버 재시작 후 이어지며, 화면 왼쪽 위 방문자 수를 누르면 **내 산책 기록**을 볼 수 있습니다. 관리자용 로컬 명령 `npm run stats`로 전체 합계를 확인하고 `npm run --silent stats -- --csv`로 방문자별 누적 기록을 내보낼 수 있습니다. 프로필 원본·날짜별 집계·소유권 해시는 다른 방문자에게 공개하지 않습니다.

현재는 브라우저 기반 익명 식별이며 사이트 저장소 삭제나 기기 변경 시 다른 방문자로 기록됩니다. 기능 적용 이전의 기록은 추정 복구하지 않습니다. 집계 정의, 저장/백업, CSV와 향후 계정 연결 구조는 [방문자 기록 안내](docs/VISITOR_DATA.md)에 정리했습니다.

## 에마 걸기와 공개 소원 관리

에마는 **그림 3종·방당 24자리·브라우저당 방마다 활성 에마 하나·24시간 게시**입니다. 소원은 36자, 선택 이름은 12자이며 공개 확인 후 걸 수 있습니다. 같은 방의 방문자에게 즉시 보이고, 3D 에마카케에 인스턴싱으로 걸립니다. 화면에는 무료·유료 같은 가격 관련 문구를 표시하지 않습니다.

- **금지어·연락처 필터** (`src/shared/moderation.ts`): URL·이메일·전화번호·SNS/LINE ID와 일본어·한국어·영어 욕설·성적 표현을 막습니다. 화면에서 바로 안내하고, 같은 검사를 서버에서도 강제합니다. 「こころすこやか」「ほしねがい」처럼 무해한 말에 섞인 경우는 통과하도록 짧은 단어는 단독으로 쓰였을 때만 막습니다.
- **신고**: 다른 사람의 에마에서 「不適切な内容を知らせる」를 누를 수 있습니다. 서로 다른 방문자 **3명**이 신고하면 자동으로 내려갑니다. 신고 수는 서버 메모리에 보관하므로 재시작하면 0부터 다시 셉니다(내려간 에마는 저장소에서 삭제되어 유지됩니다). 브라우저 기반 익명 식별이라 한 사람이 여러 브라우저로 신고할 수 있다는 한계가 있습니다.
- **관리자 내리기**: `/admin`의 에마 목록에서 신고 수를 보고 「外す」로 즉시 내릴 수 있습니다(CSRF 토큰 필요).

에마는 선택한 서버 저장소에 저장하므로 방이 비거나 서버를 재시작해도 게시 기간 동안 유지됩니다. 기존 데이터와 호환되도록 **내부 이름은 `lantern`을 그대로 씁니다**(`DATA_DIR/lanterns.json`, `shrine_lanterns` 테이블, `lantern-*` 메시지, 상품 ID `paper-warm` 등). DB 스키마 변경은 없습니다. 브라우저에 보관하는 무작위 방문 키로 내 에마를 구분하므로 저장소를 지우거나 다른 기기를 사용하면 소유권을 복구할 수 없습니다.

`LANTERN_MODE=free`가 기본입니다. `LANTERN_MODE=paid`로 시작하면 새 에마 발급을 서버에서 막고 「ただいま絵馬の奉納をお休みしています」를 표시합니다(유료라는 말은 노출하지 않음). 기존 에마는 만료 전까지 유지되고 소유자의 내리기는 계속 허용됩니다. 결제·가격·계정은 아직 없으며, 유료 전환 설계는 [수익화 설계](docs/LANTERN_MONETIZATION.md)에 있습니다.

## 같은 정원에서 만나기

1. `npm run dev`로 화면과 서버를 실행합니다.
2. 두 브라우저 또는 기기에서 **같은 주소와 같은 방**에 접속합니다. 기본 방은 `komorebi`이며 `?room=forest`처럼 방을 지정할 수 있습니다.
3. 왼쪽 위 방문자 수를 누르면 방 이름, 내 이름과 방문자 목록이 표시됩니다. **같은 방 초대 링크 복사**로 주소를 공유하거나 방 이름을 입력해 이동합니다.

같은 Wi-Fi의 휴대폰에는 터미널에 표시되는 **Network URL**을 공유하세요. `localhost` 주소는 다른 기기에서 내 컴퓨터를 가리키지 않습니다. 다른 네트워크의 친구와 만나려면 WebSocket을 지원하는 서버에 배포해야 합니다. 현재 프로젝트는 로컬에서 실행할 수 있으며 공개 배포는 하지 않았습니다.

- 방마다 최대 **12명**입니다. 방문자는 서버가 부여한 이름·옷 색·서로 다른 시작 위치로 구분됩니다. 정원이 가득 차면 입장을 안내하며 다른 방으로 자동 이동하지 않습니다.
- 위치·방향·Idle / Walk / Pray 상태를 10Hz로 공유하고, 다른 캐릭터는 약 110ms 지연 보간합니다. 방문자끼리의 물리 충돌은 적용하지 않아 길을 막지 않습니다.
- 참배 시작 시각과 자리 배정은 서버에서 결정합니다. 새전함 앞 **세 자리**에 나누어 정렬하며 두 번 절 → 두 번 박수 → 한 번 절을 함께 볼 수 있습니다. 자리가 모두 사용 중이면 기다리라는 안내가 나옵니다. 끝난 뒤에도 해당 자리에 서 있으면 자리를 차지합니다.
- 오미쿠지 결과·테미즈 동작·방문 기록은 각자의 화면에만 표시됩니다.
- 퇴장한 방문자는 제거합니다. 연결이 끊기면 다른 방문자를 지우고 재접속하며, 연결이 없어도 혼자 산책할 수 있습니다. 재접속 시 새 방문자로 시작합니다.
- unmount 시 소켓·송신 주기·재접속 타이머·페이지 이벤트와 원격 캐릭터의 Geometry / Material을 해제합니다. 공유 텍스처는 다른 캐릭터가 사용하는 동안 유지합니다.

### 서버 실행과 배포 설정

```sh
npm run build
PORT=8787 HOST=0.0.0.0 npm start
```

`dist/`와 `dist-server/`, `package.json`, lockfile 및 운영 의존성(`npm ci --omit=dev`)을 함께 배포합니다. 서버가 화면과 `/realtime`을 같은 출처에서 제공하므로 기본 설정으로 연결되며 HTTPS 화면에서는 자동으로 `wss://`를 사용합니다. 리버스 프록시는 `/realtime`의 WebSocket Upgrade를 전달해야 합니다. `/health`에서 서버 상태와 방·방문자 수를 확인할 수 있습니다.

프런트엔드와 서버를 별도로 배포할 때만 빌드 시 `VITE_REALTIME_URL=wss://서버주소/realtime`을 설정하고, 서버에는 `ALLOWED_ORIGINS=https://화면주소`를 지정하세요. 여러 출처는 쉼표로 구분합니다. 이 값에는 비밀 키를 넣지 않습니다. 개발용으로 화면만 실행하려면 `npm run dev:client`, 서버 자동 재시작은 `npm run dev:server`를 사용합니다. `npm run preview`는 별도로 실행 중인 `8787` 서버로 연결합니다.

현재 서버는 **단일 Node 프로세스의 메모리 방**입니다. 재시작하면 실시간 방문 정보가 사라지고 여러 서버 간 방은 공유되지 않습니다. 에마와 소원은 선택한 파일/DB 저장소에 유지됩니다. 기본 제한은 32개 방·256개 연결이며 실제 운영 수용량을 보장하는 부하 테스트 결과는 아닙니다. 서버는 메시지 크기·전송 빈도·맵 경계·이동 속도·주요 구조물 충돌과 참배 거리를 검사합니다. 이동은 클라이언트 예측과 서버 검증 방식이며 장식용 나무·바위의 전체 충돌 시뮬레이션이나 계정 기반 부정행위 방지는 포함하지 않습니다. 여러 서버로 확장하려면 방 라우팅과 공유 상태 계층이 추가로 필요합니다.

## GLB 교체

1. `public/models/`에 모델 파일을 추가합니다.
2. `src/game/AssetLoader.ts`의 `ASSET_MANIFEST`에 사용할 항목을 등록합니다.

```ts
export const ASSET_MANIFEST: Partial<Record<AssetId, AssetDefinition>> = {
  hall: {
    url: `${import.meta.env.BASE_URL}models/hall.glb`,
    scale: 1,
    rotationY: 0,
  },
  player: {
    url: `${import.meta.env.BASE_URL}models/player.glb`,
    scale: 1,
    rotationY: 0,
  },
};
```

지원 ID: `torii`, `hall`, `offering`, `fortune`, `ema`, `tree`, `player`.

- **축 / 피벗**: Y-up, 바닥 중심 `(0, 0, 0)`, 모델 정면 +Z. GLB의 단위는 1 = 1m입니다. 필요하면 `scale` / `rotationY`로 맞춥니다.
- **권장 크기**: 배전 원본 약 10×7m에 `HALL_LAYOUT.scale`을 적용해 경내에서는 약 20×9m(처마 포함 폭 약 21m), 도리이 너비 9m / 높이 5.5m, 캐릭터 높이 1.8m. 배전과 새전함의 크기·배치는 `layout.ts`, 나머지 배치는 `World.ts`의 `init()`에 정의되어 있습니다.
- **애니메이션**: 캐릭터 GLB에 `Idle` / `Walk` 클립이 있으면 대소문자 구분 없이 `AnimationMixer`로 전환합니다. 클립이 없어도 이동·상태 전환은 동작합니다.
- **참배**: 기본 캐릭터는 팔과 상체 리그로 전체 동작을 재생합니다. 외부 GLB는 골격 구성이 다르므로 현재 상체 대신 모델 전체의 절 / 박수 리듬을 표현합니다. 실제 손 모양을 사용하려면 `PlayerController.ts`에 해당 모델의 뼈 매핑 또는 참배 클립을 연결하세요.
- **다른 방문자**: 현재는 경량 기본 캐릭터를 사용합니다. 로컬 플레이어를 GLB로 교체해도 다른 방문자의 모델은 자동 교체되지 않으므로 `RemotePlayer.ts`에도 해당 모델 / 리그 연결이 필요합니다.
- **충돌체 / 상호작용**: 시각 모델과 독립적입니다. 크기를 크게 바꿀 때 `World.ts`의 `collide()`와 `INTERACTIONS`를 함께 조절하세요. 새전함 참배 정렬 위치는 `layout.ts`의 `OFFERING_LAYOUT.ritual`이며 현재 `(0, 0, -1.55)`입니다. 배전·새전함 GLB에도 해당 레이아웃의 배율이 추가 적용됩니다.
- 정원 Geometry 배칭은 외부 GLB를 제외하므로 모델의 계층 구조와 머티리얼은 보존됩니다.
- 없는 파일, 네트워크 오류, 파싱 오류가 발생하면 콘솔에 원인을 남기고 기본 Geometry를 사용합니다.
- 현재 GLB의 Draco / Meshopt 압축 디코더는 포함하지 않습니다. 해당 모델을 쓸 때는 `AssetLoader`에 디코더를 연결하세요.

## 성능과 검증

- 픽셀 비율은 PC 최대 2 / 터치 기기 최대 1.5, 그림자 맵은 2048 / 1024로 제한합니다.
- 정적 기본 Geometry는 머티리얼별로 병합합니다. 자갈 850개, 꽃잎 48개와 잔디 1,900개는 `InstancedMesh`를 사용합니다. 잎 카드는 불투명 알파 테스트로 처리해 투명 오브젝트 정렬 비용을 줄입니다.
- deltaTime은 최대 0.05초로 제한합니다. 숨겨진 탭에서는 업데이트·렌더링을 건너뛰고 복귀 시 시간을 초기화합니다.
- Vue HUD는 20Hz로 갱신합니다. 바닥 이동 경로는 요청 시에만 계산합니다.
- Three.js는 별도 번들입니다. 약 580kB(압축 전)로 Vite 기본 청크 크기 안내가 나올 수 있습니다.
- 목재와 잎 텍스처는 `public/textures/`의 1024px WebP이며 합계 약 0.5MB입니다(이전 PNG 5.2MB). 생성 방식과 최종 프롬프트는 [텍스처 기록](public/textures/README.md)에 있습니다. 지면·석재·옷감 질감과 하늘은 코드에서 생성합니다. 텍스처 로드 실패 시 폴백하며, 늦게 완료된 이미지도 폐기합니다.
- 로딩 화면은 셰이더 컴파일과 텍스처 업로드(`compileAsync`)가 끝난 뒤에 사라지므로 첫 화면이 빈 캔버스로 보이지 않습니다.
- Google Fonts는 HTML `<link>`와 preconnect로 불러오고 실제 쓰는 굵기(고딕 400/500/700, 명조 400/600)만 요청합니다. 사용할 수 없으면 로컬 폰트로 폴백합니다.
- 게임 테스트는 충돌·맵 경계·프레임률별 이동·참배·자원 해제·모델 폴백·경로 탐색·카메라를 검사합니다. 멀티플레이 테스트는 실제 로컬 WebSocket으로 입퇴장·이동·방 분리·12명 제한·잘못된 이동·동시 참배·출처 제한을 검증하고, 클라이언트 재접속·방 전환·소켓 / 타이머 정리·원격 캐릭터 보간과 공유 텍스처 보존도 확인합니다. 테스트 환경은 로컬 소켓 포트 바인딩을 허용해야 합니다.
- PC / 모바일 크기의 브라우저에서 UI와 입력을 확인합니다. 실제 모바일 하드웨어별 FPS 측정은 별도로 필요합니다.

실시간 날씨, 실제 새전과 결제는 구현하지 않습니다. 에마 소원 직접 작성과 저장은 지원합니다. 운세는 오락용이며 방문 기록은 현재 페이지에서만 유지됩니다. 현재 시각 모델은 프로시저럴 모델과 이미지 텍스처를 조합한 프로토타입입니다. 실제 촬영 신사나 고정밀 스캔 모델은 포함하지 않으며, GLB를 연결해 표현을 확장할 수 있습니다.
